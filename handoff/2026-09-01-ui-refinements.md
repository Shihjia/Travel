## 需求背景

使用者看過線上版本後提出的呈現方式調整：逐日行程頁的天氣資訊佔掉一整塊版面，希望改成右上角的小圖示；總覽頁的飯店／班機卡片裡，連結都是文字列，希望改成圖示放在名稱旁邊，並把「查看設施」提到最前面。另外順便解決上一份規格驗收時發現的飯店名稱用詞不一致問題。

## 需求 1：逐日行程頁的天氣改成右上角圖示

**現況**：day 頁面的 `<div class="card weather-panel" id="weather-box">` 是 `<main>` 裡最上面的一整塊卡片，佔掉不少版面；hero 右上角則是一個純裝飾用、沒有意義的 `☀️`（`.hero__sun`）。

**要求**：把天氣搬到 **hero 的右上角**，取代那個裝飾用的太陽，`<main>` 裡原本的整塊天氣卡片移除。

顯示內容（三個資訊都要有）：
1. **天氣圖示** — 依 WMO weathercode 對應晴天／多雲／陰天／雨天等（`script.js` 既有的 `WEATHER_ICONS` 對照表已經涵蓋，沿用即可，維持 emoji 呈現，與全站風格一致）
2. **溫度** — 最低～最高，例如 `24° - 28°`
3. **降雨機率** — 例如 `☔ 30%`

**尚未進入預報範圍時（重要，目前 6 天全部都是這個狀態）**：
- 使用**統一的圖示**（建議 `🗓️`，或一個淡化的天氣圖示，6 天全部一致），不要用會被誤認成「當天是晴天」的 `☀️`／`🌤️`。
- 搭配統一說明文字，內容意思要是「還查不到，出發前再看」，例如：`預報未開放` ＋ 更小的一行 `出發前約 2 週開放查詢`。文案你可以微調得更順，但**六天必須一致**。
- 現在（2026-09-01）距離出發還有一個半月，所以你在本機看到的一定是這個狀態；這是正確行為不是 bug。10 月上旬之後會自動變成實際預報。

版面要求：
- 位置：`.hero` 內絕對定位於右上角，與 `.hero__back`（左上角返回連結）同一水平帶但靠右，不可重疊。
- 外觀：半透明白底的小圓角卡片（例如 `rgba(255,255,255,0.22)` ＋ `backdrop-filter: blur`），文字白色，在藍色漸層 hero 上要清楚可讀。
- **手機 375px**：hero 寬度變窄，天氣區塊不可與標題（`.hero__title`，例如「抵達日：那霸機場 → 波上宮 →…」）重疊或把標題擠變形。可以縮小字級、改成更精簡的排法（例如圖示與溫度同一行、降雨機率換行），必要時允許在手機改放在標題下方，但**六天要一致**。
- 六個 day 頁面都要套用，寫法一致。

實作建議：
- `script.js` 的 `loadWeather(containerId, lat, lon, dateStr)` 新增第 5 個參數 `options`，用 `options.variant === "badge"` 走新的右上角版型；**不傳 options 時維持現有行為**，這樣總覽頁 `index.html` 逐日卡片裡的小天氣（`.day-card__weather`）完全不用改、也不會壞。
- 「尚未進入預報範圍」與「抓取失敗」目前共用 `weatherPendingHtml()`，badge 版型也要有對應的精簡版。

**不要動**：總覽頁逐日卡片上的小天氣維持現狀。

## 需求 2：飯店／班機卡片的連結改成圖示

### 2-1　飯店卡（總覽頁「🏨 住宿資訊」）

**現況**（`index.html` 第 131 行附近）：展開後的最後一行是三個文字連結並排 —— `飯店官網 →`、`Google 地圖 →`、`查看設施／餐廳詳情 →`。

**改成**：

- **卡片標題列**：飯店名稱右邊緊接著兩個圖示連結
  - 🌐 飯店官網（`h.website`）
  - 📍 Google 地圖（`h.mapUrl`）
  - 兩者都 `target="_blank" rel="noopener"`，並加上 `aria-label` 與 `title`（例如 `title="飯店官網"`），滑鼠移上去看得到說明。
  - **⚠️ 實作重點**：`.info-card__head` 整塊是可點擊的展開／收合觸發區，圖示連結必須 `e.stopPropagation()`，否則點官網會順便把卡片收起來。請實際點測。
  - 點擊區域至少 32×32px（手機好按）。
- **展開後的內容**：**「查看設施／餐廳詳情 →」移到第一列**，放在「房型」之前，並且做成明顯一點的樣式（例如 `.timeline-link` 那種膠囊按鈕，而不是純文字），因為這是使用者最想點的東西。
- 展開內容裡**移除**原本的官網／地圖文字連結（已經移到標題列了）。
- 順便把展開內容裡「**設施：**含早餐・私人停車位…」這一列的標籤改成「**房價包含：**」。原本叫「設施」會跟「查看設施詳情」混淆，那一行其實講的是房價含什麼。

### 2-2　班機卡（總覽頁「✈️ 班機資訊」）

- **卡片標題列**：航班名稱（例如「去程・長榮航空 BR112」）右邊加一個 🌐 圖示連結到 `f.website`，規格同上（新分頁、aria-label／title、stopPropagation、32×32px 點擊區）。
- 展開內容裡**移除**原本最後一行的「前往航空公司官網 →」文字連結。
- 其他欄位（機型／起飛／抵達／行李／提醒）維持不變。

## 需求 3：統一飯店名稱用詞（解決上一份規格的待確認事項）

目前 `itinerary.js` 裡飯店1 有兩種中譯混用：`hotels[0].name` 是「沖繩嘉利吉海灘海洋溫泉度假村」，但逐日行程與打包清單裡用的是「喜璃癒志海灘渡假飯店」（兩者都是 かりゆしビーチリゾート 的中譯）。

**規劃端決定：用結構化方式解決，不是二選一。**

在 `hotels` 兩個物件各新增一個 `shortName` 欄位：

```js
{
  id: "hotel1",
  name: "沖繩嘉利吉海灘海洋溫泉度假村",      // 完整官方名稱，維持不動
  shortName: "喜璃癒志海灘渡假飯店",          // 新增
  // ...其餘欄位不動
},
{
  id: "hotel2",
  name: "沖繩國際通那霸棕櫚皇家度假飯店",     // 維持不動
  shortName: "那霸棕櫚皇家度假飯店",          // 新增
  // ...其餘欄位不動
}
```

使用原則：
- **`name`（完整名稱）**：只用在總覽頁的飯店卡標題、`hotel1.html` / `hotel2.html` 詳情頁的頁首。
- **`shortName`（簡稱）**：其他所有地方 —— 逐日行程時間軸的標題與說明、打包清單的「訂房確認信（…／…）」那一項，日後採買推薦頁若有提到也用簡稱。
- 這次請把 `days` 裡各 `items` 目前寫死的飯店名稱、以及 `packingList` 那一項，都改成與 `shortName` 一致的字串（**字面一致即可，不需要改寫成程式取值**，維持資料檔好讀）。
- ⚠️ 打包清單那一項的文字會變動（「喜璃癒志海灘渡假飯店」本來就一致，實際只有確認是否需要調整；若字串有任何變動，使用者對該項的既有打勾會失效 —— 現在還沒開始打包，可以接受，不用做資料遷移）。
